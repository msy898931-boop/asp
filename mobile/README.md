# ASTRA mobile app

A phone app for the ASTRA backend. It is a **PWA** (installable web app): no
store account, no build step needed to use it. You open one URL once and add it
to the home screen; after that it opens full-screen like any other app. A signed
`.apk` is also published for those who prefer a file install.

## Access gate

The deployed app is **keyed**. Until the key is entered it shows a one-field
unlock screen; a first request without the key returns **HTTP 401**, which is the
gate working, not a broken deploy. The key is stored in the `astra_key` cookie.

## Deployed instance

Live on Render (free plan): **https://astra-xlp9.onrender.com**

Open it on the phone and "Add to Home screen". On the free plan the service
sleeps after 15 minutes idle; the first open then cold-starts in about a minute.
Verify a deployment (app, API, live reading, bot) with:

```bash
scripts/check_deploy.sh https://astra-xlp9.onrender.com
```

## What it shows

- **Live price** — a ticker under the header: the newest closed close and its
  change against the prior close, for the selected timeframe.
- **Status** — a gauge for system health, plus mode, startup stage, symbol and
  the market-data source (clearly labelled when it is the synthetic replay feed).
- **Signal** — direction, regime, entry / stop / target / R:R, score and context.
- **Chart** — closed-bar candles for the nine canonical timeframes.
- **Bridge** — the loopback market-data link's own state.

Everything is read-only and shadow-mode: the app never places trades, and the
footer states this. The bridge stays bound to `127.0.0.1`; the launcher only
proxies `GET` requests to it.

## Client source layout

The client is plain JavaScript with no build step. `index.html` loads nine
classic scripts in a fixed order — `app.js`, then `i18n`, `panels`, `advisor`,
`tracker`, `alerts`, `vol`, `akoan`, `ticker` — and they share one global scope,
exactly as a single file did before the split. `app.js` holds the shared state
and the network helpers, so it must stay first. Each script is precached in
`sw.js` and stamped with the build token by `serve_mobile.py`; the
`ClientScriptContractTest` in `test_serve_mobile.py` pins that, so a new script
cannot ship half-wired.

## Tests

Two layers, both driving the real shell in a real Chromium through Playwright:

- `test_dom_browser.py` aborts every live endpoint and proves the shell is fully
  navigable and never throws with a dead backend.
- `test_dom_data.py` answers those endpoints from the canonical fixtures in
  `scripts/mock_api.py` (plus a synthetic candle series) and asserts on the
  rendered DOM — the status, signal, chart, volatility and ticker panels show
  real values, and a cached reading paints with its `offline` label when the
  backend is gone. This is the layer that catches a renderer reading the wrong
  key; a text test and a dead-backend test both pass while the panel is empty.

Both skip (never fail) when Playwright is absent.

## Run the server

The backend must already be running (it publishes the loopback API on 8790 and
the bridge on 8791). Then:

```bash
python3 mobile/serve_mobile.py --host 0.0.0.0 --port 12001 \
    --api-port 8790 --bridge-port 8791
```

Point the phone's browser at `http://<server-ip>:12001/`.

## Install on the phone (e.g. Moto G7, Android 9)

1. Connect the phone to the same network as the server (or use the server's
   public URL).
2. Open the app URL in **Chrome**.
3. Tap the **⋮** menu → **Add to Home screen** → **Install**.
4. Launch it from the home screen. It opens standalone, with its own icon.

If the URL is plain `http://` on the LAN, Chrome still installs it (the service
worker needs a secure context, so on `http://` the app runs but does not cache
offline; over `https://` it also works offline).

## Offline behaviour

The service worker caches the **shell** (HTML/CSS/JS/icons), so the app opens
offline instead of showing the browser's error page. Live data is never served
from the cache — a stale reading presented as live would be a lie. That covers
the panel readings too (`vol.json`, `akoan.json`): the volatility panel stamps
the time it *rendered*, not the time the data was computed, so a cached reading
would look freshly computed. `ServiceWorkerGateTest` pins the never-cache rule.

The app separately keeps the **last successful reading** in `localStorage`
(`astra-last-read`). On a cold, offline start it paints that reading, and the
banner says `offline · showing the last reading` with its age (`3m ago`). The
moment the network returns, the live poll replaces it. The cache is versioned,
so a shape change is discarded rather than misread as current.

## Notes

- Icons are generated by `icons/make_icons.py` (standard library only) and are
  committed, so no image tooling is required to run the app.
- The fonts (Fraunces, IBM Plex Mono) load from Google Fonts when online and
  fall back to system serif/monospace offline.
